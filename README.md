# CannyGA — подбор порогов Кэнни генетическим алгоритмом

Программа выделяет контуры на изображении алгоритмом Кэнни, автоматически подбирая его пороги под конкретное изображение генетическим алгоритмом, и показывает результат рядом с «обычным» Кэнни с фиксированными порогами — визуально и по числовым метрикам.

Python + OpenCV + Tkinter. Лабораторная работа по дисциплине «3D моделирование и техническое зрение» (КНИТУ-КАИ, кафедра САПР).

## Зачем это нужно

Качество работы алгоритма Кэнни определяется двумя порогами: нижним и верхним. При слишком низких значениях карта контуров зарастает шумом, при слишком высоких — теряются границы объектов. Универсальных значений не существует: они зависят от освещённости, контраста и содержания кадра, а вручную подбирать их долго.

Генетический алгоритм делает это сам: особь — пара порогов, приспособленность — оценка качества полученной карты контуров.

## Запуск

```bash
git clone <URL этого репозитория>
cd canny-ga
pip install -r requirements.txt
python main.py
```

Нужен Python 3.9+. Дальше: «Открыть изображение…» → при необходимости поправить параметры → «Подобрать пороги» → «Сохранить результат».

Консольный режим — без окна, удобен для отчёта и пакетной обработки:

```bash
python main.py photo.jpg                      # параметры по умолчанию
python main.py photo.jpg -p 40 -g 60 -t 5     # популяция 40, 60 поколений, целевая доля контуров 5 %
python main.py photo.jpg --seed 42            # воспроизводимый результат
```

Он печатает ход поиска по поколениям, сравнение с фиксированными порогами и сохраняет обе карты контуров рядом с исходным файлом.

## Структура проекта

| Файл | Назначение |
|---|---|
| `edges.py` | Загрузка изображения, вызов Кэнни, метрики качества контуров |
| `ga.py` | Генетический алгоритм: особи, отбор, скрещивание, мутация |
| `gui.py` | Графический интерфейс на Tkinter |
| `main.py` | Точка входа: графический или консольный режим, разбор аргументов |

Модули не перемешаны: `ga.py` ничего не знает про OpenCV и Tkinter, а `edges.py` — про генетический алгоритм. Поэтому вместо Кэнни можно подставить другой оператор выделения границ или другую функцию качества, не трогая остальной код.

## Как работает генетический алгоритм

**Особь** — пара порогов `(t1, t2)`, где `0 ≤ t1 < t2 ≤ 255`. Особи создаются сразу корректными, поэтому нежизнеспособных вариантов в популяции нет.

**Приспособленность** — оценка карты контуров, полученной с этими порогами:

```
score = −10 · |доля контурных пикселей − целевая| − шум + 0.5 · непрерывность
```

- *доля контурных пикселей* — сколько пикселей отнесено к контурам (целевое значение задаётся, по умолчанию 10 %);
- *шум* — доля одиночных контурных пикселей, у которых нет ни одного соседа;
- *непрерывность* — доля контурных пикселей, имеющих два и более соседей, то есть лежащих на линии, а не рассыпанных по кадру.

Хорошая карта контуров — это длинные связные линии, поэтому одной доли контурных пикселей для оценки недостаточно.

**Шаг эволюции:** элита (2 лучшие особи) переходит в новое поколение без изменений, остальные потомки получаются турнирным отбором родителей, смешивающим скрещиванием BLX-α и мутацией, сила которой убывает к последним поколениям — сначала алгоритм исследует пространство порогов, затем уточняет найденное решение. Значения приспособленности кэшируются: для одной и той же пары порогов Кэнни считается один раз.

## Пример результата

Тестовое изображение с геометрическими фигурами, целевая доля контуров 3 %:

| | Пороги | Контурных пикселей | Непрерывность | Оценка |
|---|---|---|---|---|
| Кэнни без ГА | 100, 200 | 0.89 % | 99.8 % | +0.288 |
| Кэнни + ГА | 24, 127 | 3.33 % | 99.9 % | **+0.467** |

Фиксированные пороги на этом изображении теряют слабоконтрастные границы; алгоритм нашёл пороги, дающие нужную детализацию без роста шума.

## Ограничения

- Функция качества оценивает контуры **косвенно**, по статистике пикселей. Эталонной разметки (ground truth) нет, поэтому «лучше» здесь означает «ближе к заданной детализации при меньшем шуме», а не совпадение с ручной разметкой. Для строгой оценки нужны наборы вроде BSDS500 и метрики точность/полнота.
- Целевая доля контурных пикселей задаётся человеком: это и есть тот параметр, который заменил ручной подбор двух порогов. Его смысл, однако, куда понятнее, и он почти не зависит от яркости кадра.
- Оптимизируются только два порога. Размер гауссова сглаживания и апертура оператора Собеля фиксированы, хотя их тоже можно добавить в геном.
- Время работы растёт как популяция × поколения; на больших изображениях расчёт стоит вести на уменьшенной копии.
